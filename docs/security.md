# Security scope and dependency review

CiteRAG remains a single-user application without authentication or tenant isolation. The API can read/delete the whole local corpus for its owner. Do not expose it as an unprotected public upload service.

## Implemented controls

Secrets are backend-only and environment files are ignored. Errors do not serialize provider exception bodies. Request IDs are generated by the service; arbitrary client IDs are not echoed into logs. Structured request metrics exclude questions, excerpts, filenames, and credentials. LOG_QUERY_TEXT defaults to false. Existing legacy query_logs were preserved and may contain older private questions; that table is not exposed by monitoring.

Uploads bound both declared and streamed body sizes, including chunked requests without Content-Length. They validate extension, size, normalized filename, UTF-8 extraction, PDF page count, extracted character count, and maximum chunk count before embedding. PDF extraction and chunking run off the async event loop. Scanned PDFs still need OCR outside the app. These controls do not replace malware scanning or a sandbox for hostile PDF parsing.

The API requires explicit CORS origins and trusted hosts, checks mutation origins, applies a per-process sliding-window limit, and uses bounded provider timeout/retries. SDK transient retries use exponential backoff. CORS and rate limits are not authorization, a global quota, or a guarantee against cost abuse. Run behind an access-controlled HTTPS ingress for any remote single-user deployment.

Retrieved excerpts are JSON-encoded untrusted data under fixed system instructions. Citation IDs are checked against selected persisted chunks. Supporting excerpts stay inspectable. A valid marker does not prove semantic support or immunity to prompt injection; judge scores and human review remain separate.

## Actual dependency audit

The npm audit reported zero vulnerabilities. The initial Python audit found old-pip issues and Chroma server issues. Pip was upgraded to 26.2.2. The final raw report is `docs/dependency-audit-python-final.json`.

Four unique Chroma advisories remain for installed chromadb 1.5.9: PYSEC-2026-311, PYSEC-2026-3814, PYSEC-2026-3815, and PYSEC-2026-3813. The advisory service lists no fixed version, and the package index reported 1.5.9 as the latest release at verification. Some raw feed entries are duplicated; they are not separate vulnerabilities.

The descriptions concern Chroma HTTP-server model/collection configuration and server authorization. This application uses an embedded PersistentClient, exposes no Chroma HTTP routes, does not accept model-repository/embedding-function configuration from API users, and never enables remote model code. The optional reranker loads locally only. This narrows applicability; it does not patch the package or prove universal immunity.

`backend/security/advisory-exceptions.json` records exact package/version/IDs, rationale, invalidating conditions, and a review deadline of 29 November 2026. `scripts/audit_dependencies.py` retains raw findings and fails CI for any unreviewed vulnerability, another affected version, an expired review, or an unusable advisory-service result. CI reports the reviewed findings explicitly. It does not label the dependency audit clean.

Re-review immediately before exposing a Chroma server, adding RBAC/multi-tenancy, accepting model configuration, changing versions, or provisioning a remote reranker. A CI route test confirms no /api/v2 server paths are exposed; architectural applicability still requires human review. Renewing an exception is a maintenance decision, not an automatic date extension.

## Remaining work for public multi-user production

Authentication and authorization, tenant storage isolation, global quotas, distributed rate limiting, malware scanning, background ingestion, transactional recovery/migrations, broader adversarial evaluation, load testing, and hosted backup/restore validation remain separate work. No GitHub push, public deployment, or paid resource creation was performed.
